# 비디오 샘플러 제품 기획서

> 문서 상태: 초안  
> 작성일: 2026-11-17  
> 대상 플랫폼: React + TypeScript 웹, 향후 iOS·Android 확장

## 1. 제품 개요

### 1.1 한 줄 정의

여러 개의 짧은 동영상 클립을 패드에 등록하고, 사용자가 패드를 연주한 순서와 타이밍을 기록하여 하나의 새로운 영상으로 편집·저장하는 비디오 퍼포먼스 도구다.

음악 샘플러가 음원을 연주한다면, 비디오 샘플러는 영상과 소리를 함께 연주한다.

### 1.2 해결하려는 문제

기존 영상 편집기는 타임라인 중심이어서 즉흥적으로 영상을 연주하고 조합하기 어렵다. 비디오 샘플러는 다음 경험을 제공한다.

- 짧은 영상을 악기의 샘플처럼 수집한다.
- 키보드, 마우스 또는 터치로 영상을 즉시 연주한다.
- 여러 영상과 소리를 동시에 조합한다.
- 퍼포먼스를 기록하고 필요한 부분만 수정한다.
- 결과를 하나의 완성된 영상 파일로 저장한다.

### 1.3 주요 사용자

- 숏폼 영상 제작자
- 음악가와 비트메이커
- VJ 및 라이브 퍼포머
- 영상 콜라주를 만드는 크리에이터
- 복잡한 영상 편집기 없이 리듬 기반 영상을 만들고 싶은 일반 사용자

## 2. 핵심 사용자 경험

1. 기존 동영상 파일을 프로젝트의 **소스 영상**으로 불러온다.
2. 샘플링 모드에서 소스 영상을 재생한다.
3. 원하는 장면이 나오는 동안 16개 패드 중 하나를 누르고 있는다.
4. 패드를 누른 시점부터 뗀 시점까지의 영상과 소리가 해당 패드의 샘플로 저장된다.
5. 이미 샘플이 있는 패드를 다시 누르고 수집하면 기존 샘플을 새 구간으로 덮어쓴다.
6. 퍼포먼스 모드에서 샘플이 채워진 패드를 음악 샘플러처럼 연주한다.
7. 각 영상이 출력될 위치와 크기를 정하고 퍼포먼스를 기록한다.
8. 필요하면 기록된 타이밍을 타임라인에서 수정한다.
9. 결과를 하나의 영상 파일로 렌더링하여 저장한다.

이 제품의 기본 입력 방식은 카메라 촬영이 아니라 **기존 영상에서 구간을 실시간으로 채집하는 것**이다. 카메라 촬영은 사용자가 직접 소스 영상을 만들고 싶을 때 사용하는 보조 기능으로 둔다.

샘플링의 대표 동작은 다음과 같다.

```text
소스 영상 00:10.200 재생 중 → PAD 01 누름
소스 영상 00:12.850 재생 중 → PAD 01 뗌

결과: PAD 01 = 소스 영상의 00:10.200 ~ 00:12.850 구간
```

PAD 01에 기존 구간이 있더라도 같은 동작을 다시 수행하면 새 구간으로 교체한다. 실수로 덮어쓴 경우를 위해 최소 1회의 실행 취소를 제공한다.

예시는 다음과 같다.

- 킥 패드: 화면 왼쪽 아래에서 발을 구르는 영상
- 스네어 패드: 화면 중앙에서 손뼉을 치는 영상
- 보컬 패드: 화면 오른쪽에서 짧은 목소리를 내는 영상
- 베이스 패드: 배경 전체를 채우는 반복 영상

여러 패드를 동시에 누르면 영상이 각 위치에 함께 나타나고 소리도 하나로 믹싱된다.

## 3. 제품의 핵심 개념

### 3.1 프로젝트

하나의 영상 작업 단위다. 프로젝트는 패드, 샘플, 스테이지 설정, 퍼포먼스 이벤트와 내보내기 설정을 포함한다.

### 3.2 소스 영상

사용자가 프로젝트로 불러온 원본 동영상이다. 한 프로젝트에서 하나 이상의 소스 영상을 사용할 수 있지만, MVP의 샘플링 화면에서는 한 번에 하나의 활성 소스 영상을 재생한다.

소스 영상은 프로젝트 자산으로 보존하며, 패드를 채울 때마다 동일한 영상 데이터를 복사하지 않는다.

### 3.3 샘플

소스 영상에서 채집한 연속 구간이다. 샘플은 별도의 영상 파일이 아니라 원본 영상과 시작·종료 시점을 가리키는 비파괴 참조로 저장하는 것을 기본으로 한다.

- 소스 영상 ID
- 제목과 썸네일
- 소스 기준 시작점과 종료점
- 기본 볼륨
- 재생 속도
- 반복 여부

```ts
type VideoSample = {
  id: string;
  sourceVideoId: string;
  inMs: number;
  outMs: number;
  thumbnailTimeMs: number;
  volume: number;
  playbackRate: number;
};
```

이 구조는 같은 원본에서 여러 구간을 빠르게 채집할 수 있고 프로젝트 용량이 불필요하게 증가하는 것을 막는다. 내보내기나 프록시 생성 단계에서만 실제 프레임을 디코딩한다.

### 3.4 패드

샘플을 연주하는 입력 버튼이다. 패드는 샘플과 다음 재생·표시 설정을 연결한다.

- 재생 모드
- 키보드 단축키
- 출력 위치와 크기
- 레이어 순서
- 영상 맞춤 방식
- 볼륨과 음소거

### 3.5 패드 재생 모드

- **One-shot:** 누르면 설정된 끝 지점까지 재생한다.
- **Hold:** 누르고 있는 동안만 재생한다.
- **Toggle:** 한 번 누르면 재생하고 다시 누르면 정지한다.
- **Loop:** 설정 구간을 반복 재생한다.
- **Retrigger:** 재생 중 다시 누르면 처음부터 재생한다.

샘플링 모드에서 패드를 누르고 있는 동작은 **구간 채집 제스처**이며, 퍼포먼스 모드의 Hold 재생과는 구분한다. MVP의 퍼포먼스 재생은 One-shot + Retrigger와 패드별 Loop를 구현한다. Retrigger는 샘플 재생 중 패드를 다시 누르면 현재 재생을 중단하고 IN 지점부터 즉시 다시 시작한다.

### 3.6 샘플링 세션

소스 영상을 재생하면서 패드에 구간을 수집하는 상태다.

샘플링 세션의 규칙은 다음과 같다.

- 패드를 누르는 `pointerdown` 시점의 소스 재생 위치를 시작점으로 기록한다.
- 패드를 떼는 `pointerup` 시점의 소스 재생 위치를 종료점으로 기록한다.
- 키보드 입력도 `keydown`과 `keyup`을 같은 규칙으로 사용한다.
- 패드를 누르는 동안 해당 패드를 녹화 상태로 강조하고 수집 길이를 실시간으로 표시한다.
- 패드를 떼면 썸네일과 샘플 길이를 즉시 갱신한다.
- 기존 샘플이 있는 패드에 새 구간을 수집하면 기존 할당을 교체한다.
- 포인터가 버튼 밖으로 나가도 누름 상태를 추적하고, 입력 취소 시 안전하게 수집을 종료한다.
- 소스 영상이 끝나거나 변경되면 진행 중인 수집을 자동 종료한다.
- 소스 영상이 일시 정지된 상태에서는 새 수집을 시작하지 않는다.
- 너무 짧은 입력은 실수로 간주하며, MVP에서는 최소 길이를 약 100ms로 둔다.

MVP에서는 한 번의 누름으로 하나의 연속 구간만 저장한다. 여러 불연속 구간을 하나의 패드에 이어 붙이는 기능은 후속 기능으로 둔다.

### 3.7 스테이지

최종 영상이 합성되는 출력 화면이다. 패드가 놓인 위치를 영상 위치로 그대로 사용할 수도 있고 패드와 출력 위치를 별도로 설정할 수도 있다.

MVP에서는 다음 레이아웃을 제공한다.

- 전체 화면
- 2×2 그리드
- 4×4 그리드
- 제한된 자유 배치

### 3.8 퍼포먼스 이벤트

완성 영상을 화면 녹화 결과만으로 저장하지 않고 사용자의 입력을 이벤트로 기록한다.

```ts
type TriggerEvent = {
  id: string;
  padId: string;
  startedAtMs: number;
  endedAtMs?: number;
  action: "start" | "stop";
};
```

렌더링할 때 기록된 이벤트를 같은 시간 순서로 다시 실행한다. 이 방식은 미리보기 프레임이 잠시 떨어지더라도 최종 결과물의 프레임과 음향 싱크를 일정하게 만드는 기반이 된다.

### 3.9 패드별 루프 스테이션

각 패드는 다른 패드와 독립적으로 Loop를 켜고 끌 수 있다. 하나의 프로젝트에 등록된 여러 소스 영상에서 채집한 샘플도 각자의 `sourceVideoId`를 유지한 채 동시에 반복 재생한다.

1차 프로토타입의 Loop는 샘플의 IN~OUT 길이를 그대로 반복한다.

- PAD 01 Loop ON/OFF가 다른 패드에 영향을 주지 않음
- Loop 중 같은 패드를 누르면 IN 지점부터 Retrigger
- Loop OFF 시 현재 회차가 끝난 뒤 정지
- 서로 다른 소스 영상의 샘플도 동시에 Loop 가능

샘플 길이가 BPM 그리드의 배수가 아니면 메트로놈과 장기적으로 어긋날 수 있다. 후속 루프 스테이션에서는 다음 기능을 추가한다.

- 1·2·4마디 루프 길이 선택
- 다음 박 또는 다음 마디에서 Loop 시작
- 샘플 길이를 마디에 맞추는 Trim, Time Stretch 또는 빈 구간 유지 정책
- 패드별 Overdub 이벤트 기록
- 패드별 Mute, Clear, Undo
- 모든 루프가 공유하는 마스터 Web Audio 시계

## 4. MVP 범위

### 4.1 샘플 관리

- 동영상 파일 불러오기
- 여러 소스 영상의 프로젝트 등록 및 전환
- 소스 영상 재생, 일시 정지, 탐색
- 재생 중 패드를 누르고 있는 구간을 샘플로 수집
- 최대 16개 패드에 샘플 구간 저장
- 같은 패드를 다시 샘플링하여 기존 구간 덮어쓰기
- 샘플링 덮어쓰기 실행 취소
- 패드별 샘플 길이와 원본 타임코드 표시
- 썸네일 자동 생성
- 샘플 이름 변경 및 삭제
- 수집 후 시작점과 종료점 미세 조정
- 볼륨 조절 및 음소거
- One-shot + Retrigger 재생 모드
- 패드별 Loop ON/OFF

#### 샘플 길이 미세 조정 (후속 기능)

패드로 빠르게 수집한 구간은 시작점과 종료점에 불필요한 프레임이 포함될 수 있으므로 별도의 정밀 편집 화면을 제공한다.

- IN/OUT 핸들을 드래그하여 구간 길이 조절
- 프레임 단위 이전·다음 이동
- 1ms, 10ms, 1프레임 단위 증감 버튼
- 조정 중 구간 반복 미리보기
- 원본 파형과 영상 썸네일 스트립 표시
- IN/OUT 변경 전후 실행 취소
- 원본 영상은 수정하지 않고 타임코드만 변경하는 비파괴 편집

미세 조정은 샘플 자체의 재생 범위를 변경한다. 퍼포먼스 이벤트의 시작 위치를 박자에 맞추는 Quantize와는 별개의 기능이다.

### 4.2 퍼포먼스

- 마우스, 터치, 키보드로 패드 실행
- 여러 영상 동시 재생
- 패드 실행 상태 표시
- 전체 정지
- BPM 설정
- 메트로놈과 카운트인
- 퍼포먼스 녹화
- 녹화 취소 및 다시 녹화

### 4.3 스테이지

- 16:9 출력 화면
- 패드별 출력 위치와 크기 설정
- `contain` 및 `cover` 맞춤 방식
- 레이어 순서 설정
- 배경색 설정
- 최대 4개 영상 동시 출력

### 4.4 타임라인

- 기록된 패드 이벤트 표시
- 이벤트 이동 및 삭제
- 전체 영상 길이 조절
- BPM 단위 Quantize
- 재생 헤드 이동
- 구간 반복 재생

#### Quantize / 박자 맞춤 (후속 기능)

사용자가 패드를 조금 빠르거나 늦게 눌러도 기록된 이벤트의 시작점을 BPM 그리드의 가장 가까운 박자 위치로 정렬하는 기능이다. GarageBand 등 음악 제작 도구에서 일반적으로 **Quantize(퀀타이즈, 양자화)**라고 부른다.

제공 옵션:

- Off: 입력 타이밍을 그대로 유지
- 1/4: 4분음표 단위로 정렬
- 1/8: 8분음표 단위로 정렬
- 1/16: 16분음표 단위로 정렬
- 후속 확장: 1/32, 셋잇단음표, 스윙, Quantize 강도

Quantize 기준은 프로젝트 BPM과 첫 마디 시작점이다. 기본 동작은 연주 중 소리를 지연시키지 않고 즉시 재생한 뒤, 녹화된 이벤트의 시작 시각만 가장 가까운 그리드로 보정하는 방식으로 한다. 선택 기능으로 다음 그리드까지 기다렸다가 재생하는 실시간 Launch Quantize를 제공할 수 있지만, 입력 지연처럼 느껴질 수 있으므로 일반 Quantize와 구분한다.

Quantize 적용 전 원본 입력 시각을 보존하여 언제든 원래 타이밍으로 되돌릴 수 있어야 한다.

### 4.5 내보내기

- 720p / 30fps
- WebM 우선 지원
- 영상과 혼합 오디오 포함
- 렌더링 진행률 표시
- 결과 미리보기 및 다운로드

초기 버전의 공식 지원 범위는 Chrome·Edge 데스크톱으로 제한한다. 모바일 브라우저와 Safari는 후속 단계에서 확장한다.

## 5. MVP에서 제외할 기능

- 카메라로 소스 영상 직접 촬영
- 멀티트랙 전문 영상 편집
- 자막과 모션 그래픽 편집기
- 복잡한 색 보정
- 실시간 협업
- 클라우드 프로젝트 동기화
- 플러그인 마켓
- 라이브 스트리밍
- 무제한 동시 영상 재생
- 모든 브라우저에서 동일한 MP4 출력

제외 기능은 핵심 연주 경험과 내보내기 가능성을 검증한 이후 우선순위를 다시 정한다.

## 6. 화면 구성

### 6.1 프로젝트 홈

- 새 프로젝트

- 프로젝트 이름 변경
- 프로젝트 복제 및 삭제
- 마지막 수정 시각 표시

### 6.2 샘플링 화면

샘플링 화면은 상단의 소스 영상과 하단의 16개 패드가 한 화면에 항상 함께 보이는 구조로 만든다.

```text
┌─────────────────────────────────────────────┐
│ 소스: source-video.mp4        [소스 변경]   │
├─────────────────────────────────────────────┤
│                                             │
│                 SOURCE VIDEO                │
│                                             │
├─────────────────────────────────────────────┤
│ 00:10.200 ━━━━━━━●━━━━━━━━ 03:24.000        │
│       [◀ 5s]  [▶/Ⅱ]  [5s ▶]   속도 1.0×   │
├─────────────────────────────────────────────┤
│ [01 2.65s] [02 empty] [03 0.80s] [04 empty] │
│ [05 empty] [06 1.20s] [07 empty] [08 empty] │
│ [09 empty] [10 empty] [11 empty] [12 empty] │
│ [13 empty] [14 empty] [15 empty] [16 empty] │
├─────────────────────────────────────────────┤
│ 패드를 누르고 있는 동안 현재 구간을 수집합니다 │
│ [↶ 마지막 덮어쓰기 취소]     [퍼포먼스 이동] │
└─────────────────────────────────────────────┘
```

필수 인터랙션은 다음과 같다.

- 소스 영상 재생 중 패드를 누르면 즉시 수집을 시작한다.
- 누르고 있는 패드는 빨간색 테두리, 녹화 점과 증가하는 길이로 상태를 표시한다.
- 패드를 떼는 순간 수집을 종료하고 해당 패드에서 짧은 결과 미리보기를 보여준다.
- 채워진 패드에는 썸네일, 패드 번호와 샘플 길이를 표시한다.
- 채워진 패드를 짧게 미리 듣는 동작과 새 구간으로 덮어쓰는 동작이 충돌하지 않도록 샘플링 모드에서는 `누르고 유지 = 수집`으로 입력 의미를 고정한다.
- 샘플 미리보기는 패드의 별도 미리보기 아이콘 또는 샘플 편집 화면에서 실행한다.
- 소스 탐색 바에서 원하는 위치로 이동한 뒤 재생을 계속하며 샘플링할 수 있다.
- 소스 영상을 바꾸어도 이미 채집한 패드는 기존 소스 참조를 유지한다.

영상 처리 로직을 React 컴포넌트 안에 직접 구현하지 않고 인터페이스와 플랫폼 어댑터로 분리한다.

```ts
interface MediaEngine {
  loadSample(sample: VideoSample): Promise<void>;
  trigger(padId: string, time: number): void;
  stop(padId: string, time: number): void;
  seek(time: number): Promise<void>;
}

interface RenderEngine {
  render(
    project: Project,
    events: TriggerEvent[],
    options: RenderOptions,
  ): Promise<RenderedVideo>;
}
```

웹에서는 브라우저 API를 사용하고 향후 모바일에서는 같은 인터페이스 뒤에 네이티브 미디어 엔진을 연결한다.

## 8. 웹 구현 전략

### 8.1 실시간 오디오

정밀한 오디오 타이밍은 여러 `<video>` 요소의 `play()` 호출에 맡기지 않고 Web Audio API의 공통 시계를 기준으로 스케줄링한다. `AudioContext.currentTime`을 마스터 시계로 사용하고 짧은 look-ahead 구간의 이벤트를 미리 예약한다.

참고: [MDN Web Audio 스케줄링](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Advanced_techniques)

### 8.2 실시간 영상

활성화된 샘플의 현재 프레임을 하나의 Canvas 또는 WebGL 스테이지에 합성한다.

- `requestAnimationFrame` 기반 화면 갱신
- 영상별 위치와 크기에 맞춰 프레임 렌더링
- 레이어 순서 적용
- 추후 필터, 크로마키, 블렌드 모드 확장

Canvas 화면은 `captureStream()`으로 영상 스트림을 만들 수 있다.

참고: [MDN Canvas captureStream](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/captureStream)

### 8.3 MVP 내보내기

첫 버전에서는 다음 방식을 사용한다.

1. Canvas에서 영상 스트림을 생성한다.
2. Web Audio에서 혼합 오디오 스트림을 생성한다.
3. 두 스트림을 하나의 `MediaStream`으로 결합한다.
4. `MediaRecorder`로 WebM 파일을 저장한다.

이 방식은 구현이 비교적 단순하지만 실시간으로 재생하면서 녹화하므로 기기 성능과 브라우저 상태의 영향을 받을 수 있다.

참고: [MDN MediaRecorder](https://developer.mozilla.org/en-US/docs/Web/API/MediaRecorder/MediaRecorder)

### 8.4 정식 렌더링

후속 버전에서는 WebCodecs를 사용해 각 프레임을 생성하고 인코딩하는 오프라인 렌더러를 추가한다. WebCodecs는 코덱 처리를 담당하지만 MP4 또는 WebM 컨테이너를 직접 만들지 않으므로 별도의 muxer가 필요하다.

참고: [MDN WebCodecs](https://developer.mozilla.org/en-US/docs/Web/API/WebCodecs_API)

ffmpeg.wasm도 대안이지만 초기 로드 크기, 메모리 사용량, 모바일 처리 속도를 검증해야 한다.

참고: [ffmpeg.wasm 공식 문서](https://ffmpegwasm.netlify.app/docs/overview/)

권장 발전 순서는 다음과 같다.

1. Canvas + Web Audio + MediaRecorder
2. WebCodecs 기반 결정론적 렌더링
3. 모바일 네이티브 렌더러 또는 선택적 서버 렌더링

## 9. 데이터 및 저장 전략

### 9.1 프로젝트 데이터

프로젝트 JSON에는 다음 정보만 저장한다.

- 프로젝트 메타데이터
- 소스 영상 파일 참조
- 샘플별 소스 영상 ID와 시작·종료 타임코드
- 패드 설정
- 스테이지 레이아웃
- 퍼포먼스 이벤트
- 내보내기 설정

### 9.2 미디어 파일

원본 영상 Blob은 일반 UI 상태 저장소에 넣지 않고 별도의 미디어 저장 계층에서 관리한다.

- 웹: IndexedDB 또는 브라우저 파일 저장소
- 네이티브: 기기 파일 시스템
- 프로젝트 모델: 실제 Blob 대신 미디어 ID 참조

### 9.3 자동 저장

- 설정과 이벤트는 변경 후 자동 저장한다.
- 대용량 미디어 저장 실패를 사용자에게 명확하게 알린다.
- 프로젝트를 삭제할 때 참조되지 않는 미디어도 함께 정리한다.

## 10. 모바일 앱 확장 전략

웹 프로젝트를 앱으로 패키징하는 첫 번째 선택지는 Capacitor로 한다. Capacitor는 기존 React 프로젝트에 추가할 수 있고, 필요한 경우 Swift 또는 Kotlin으로 네이티브 기능을 플러그인 형태로 연결할 수 있다.

참고: [Capacitor 공식 문서](https://capacitorjs.com/docs)

권장 단계는 다음과 같다.

1. React + TypeScript 웹 버전 개발
2. PWA 대응
3. Capacitor로 iOS·Android 패키징
4. 영상 인코딩이 성능 한계에 도달하면 네이티브 렌더링 플러그인 추가

React Native로 전환하는 것도 가능하지만 웹 UI와 Canvas·Web Audio 코드는 상당 부분 다시 작성해야 한다. 프로젝트 데이터 모델, 타임라인 계산, 이벤트 기록과 BPM 로직은 공유할 수 있다.

참고: [React Native 플랫폼별 코드](https://reactnative.dev/docs/platform-specific-code)

따라서 초기 아키텍처는 `공통 코어 + 플랫폼별 미디어 어댑터 + Capacitor 우선`으로 구성한다.

## 12. 주요 위험과 대응

### 12.1 패드 반응 지연

원본 영상을 누를 때마다 로딩하면 패드 반응이 늦어진다.

대응 방안:

- 프로젝트를 열 때 샘플 사전 로딩
- 편집용 저해상도 프록시 생성
- 첫 프레임 미리 디코딩
- MVP에서 영상 길이와 해상도 제한

### 12.2 동시 재생 시 프레임 저하

다수의 고해상도 영상을 동시에 디코딩하는 것은 현실적이지 않다.

MVP 권장 제한:

- 샘플당 최대 10초
- 입력 영상 최대 1080p
- 미리보기는 720p 프록시
- 동시 활성 영상 최대 4개
- 출력 720p / 30fps

### 12.3 영상과 오디오의 싱크 이탈

영상 요소 각각의 재생 시간을 기준으로 삼지 않고 하나의 마스터 시계를 사용한다.

- Web Audio clock을 실시간 마스터로 사용
- 이벤트 시간을 고정 타임베이스로 저장
- 최종 렌더링은 프레임 번호를 기준으로 계산
- 렌더링 상태를 UI 상태와 분리

### 12.4 프로젝트 용량 증가

- 프로젝트 JSON과 원본 미디어를 분리한다.
- 저장 용량과 예상 출력 크기를 표시한다.
- 저해상도 프록시와 원본의 생명주기를 따로 관리한다.
- 네이티브에서는 기기 파일 시스템 어댑터를 사용한다.

### 12.5 브라우저 및 코덱 차이

- 내보내기 전에 `MediaRecorder.isTypeSupported()` 또는 코덱 지원 여부를 검사한다.
- MVP의 공식 지원 브라우저를 제한한다.
- 지원되지 않는 조합은 대체 포맷을 제안한다.
- 장기적으로 결정론적 렌더러나 서버 렌더링을 제공한다.

## 13. 비기능 요구사항

### 13.1 성능 목표

- 패드 입력 후 오디오 시작 체감 지연 최소화
- 720p 미리보기에서 최대 4개 샘플 동시 재생
- 30초 프로젝트를 메모리 초과 없이 내보내기
- 장시간 사용 후에도 미디어 객체와 디코더 자원 정상 해제

### 13.2 안정성

- 자동 저장
- 렌더링 실패 시 원인을 사용자에게 표시
- 브라우저 탭 전환 또는 장치 변경 시 안전한 복구
- 손상된 미디어 파일을 프로젝트 전체 실패와 분리

### 13.3 접근성 및 입력

- 모든 패드에 키보드 접근 제공
- 패드별 읽을 수 있는 이름 제공
- 색상만으로 재생 상태를 구분하지 않음
- 터치 환경에서 충분한 패드 크기 제공

## 14. MVP 완료 기준

다음 조건을 모두 만족하면 첫 번째 유효한 제품으로 판단한다.

- 기존 동영상을 소스 영상으로 불러올 수 있다.
- 여러 소스 영상을 등록하고 활성 샘플링 소스를 전환할 수 있다.
- 서로 다른 소스의 샘플을 네 패드에 유지한 채 동시에 재생할 수 있다.
- 소스 영상을 재생하면서 패드를 누른 구간이 해당 패드에 저장된다.
- 패드를 다시 샘플링하면 기존 구간이 교체되고 마지막 덮어쓰기를 취소할 수 있다.
- 같은 소스 영상에서 16개의 서로 다른 구간을 빠르게 수집할 수 있다.
- 패드에 저장된 구간의 시작·종료 타임코드와 길이가 정확하다.
- 16개 패드에 서로 다른 샘플 구간을 등록할 수 있다.
- 최소 4개 영상을 동시에 재생할 수 있다.
- 누른 순서와 타이밍이 기록된다.
- 녹화 결과를 다시 재생했을 때 퍼포먼스가 동일하다.
- 이벤트를 이동하거나 삭제할 수 있다.
- 30초 분량의 결과를 720p 영상으로 다운로드할 수 있다.
- 30초 결과물에서 체감 가능한 A/V 싱크 이탈이 없다.
- 프로젝트를 닫았다 다시 열 수 있다.

## 15. 단계별 개발 로드맵

### Phase 0. 기술 검증

- 하나의 소스 영상 파일 로딩과 재생
- 재생 중 4개 패드의 누름·해제 타임코드 수집
- 수집된 구간의 비파괴 저장과 덮어쓰기
- 패드별 수집 구간 즉시 재생
- 2×2 Canvas 합성
- 키보드 패드 입력
- Web Audio 기반 소리 재생
- 이벤트 기록 및 재실행
- 10초 WebM 내보내기

이 단계에서는 먼저 `재생 중 누르고 있기 → 정확한 구간 채집 → 즉시 패드 재생` 흐름을 검증한다. 그다음 입력 지연, 동시 디코딩 성능과 싱크를 검증한다.

### Phase 1. 데스크톱 웹 MVP

- 16개 패드
- 소스 영상 중심 샘플링 화면
- 패드 구간 덮어쓰기와 실행 취소
- 여러 소스 영상 등록 및 패드별 소스 참조
- 패드별 독립 샘플 길이 Loop
- 샘플 편집
- 고정 레이아웃
- 퍼포먼스 녹화
- 간단한 타임라인
- 프로젝트 자동 저장
- 720p WebM 내보내기

### Phase 2. 편집 기능 강화

- 자유 배치
- 샘플 IN/OUT 길이 미세 조정
- 1/4, 1/8, 1/16 Quantize
- Quantize 적용 전 원본 타이밍 복원
- 1·2·4마디 동기화 루프 및 다음 마디 Launch
- 패드별 Overdub, Mute, Clear, Undo
- 속도와 레이어 편집
- 프록시 미디어 생성
- WebCodecs 렌더러 검토 및 도입
- MP4 내보내기 검토

### Phase 3. 모바일 앱

- PWA 최적화
- Capacitor 앱 패키징
- 모바일 파일 권한 처리
- 카메라 기반 소스 영상 촬영 검토
- 모바일 저장소 어댑터
- 필요 시 네이티브 인코딩 플러그인

## 16. 예상 개발 범위

1인 개발 기준의 대략적인 범위는 다음과 같다.

- 기술 검증 프로토타입: 1~2주
- 데스크톱 웹 MVP: 6~10주
- 모바일 대응 및 안정적인 고품질 렌더링을 포함한 베타: 3~5개월

실제 일정은 자유 배치 편집, MP4 출력, 모바일 지원 범위와 디자인 완성도에 따라 달라진다.

## 17. 최종 제안

첫 번째 프로토타입은 다음 기능으로 제한한다.

- 여러 소스 영상 불러오기 및 전환
- 독립적으로 동작하는 4개 패드
- 소스 재생 중 패드를 누른 구간 채집
- 같은 패드 재입력 시 구간 덮어쓰기
- 마지막 덮어쓰기 실행 취소
- 채집한 구간 즉시 패드 재생
- 네 패드의 동시 영상·오디오 재생
- One-shot + Retrigger 재생
- 패드별 독립 샘플 길이 Loop
- BPM 조절이 가능한 4박자 메트로놈

이 프로토타입에서 가장 먼저 검증할 제품 가설은 “영상을 보면서 패드를 누르는 행위만으로 원하는 장면을 빠르고 재미있게 수집하고, 네 샘플을 박자에 맞춰 연주할 수 있는가”이다. 이후 입력 지연, 영상·오디오 싱크와 렌더링 품질을 검증하고 16개 패드, 자유 배치, 타임라인 편집과 모바일 앱 순서로 확장한다.
